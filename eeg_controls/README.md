# EEG control experiments on KG-GT v2

The question: does scalp EEG add anything to the kinematics when decoding muscle activity, and
if so, where? In the concurrent, non-causal setting of KG-GT v2 it does not (F = K, residual r about 0.07).
The three scripts below test what E reads, whether its maps agree with classical analyses, and whether
the EEG helps when the envelope must be forecast from the past.

The easiest way to run everything is the notebook `eeg_controls.ipynb` (generated by
`tools/build_eeg_controls_notebook.py`): one section per experiment, each with a RUN cell that saves the tables and a
PLOT cell with its own figures (saved to `eeg_controls/results/figures/`). The same steps also run from the command
line as below.

All commands run from the repository root with the project environment. Nothing here changes `main/`,
the notebooks or the default behaviour of `v2/` (the causal mode and the horizon are opt-in config keys).

| # | script | trains? | default output | time |
|---|--------|---------|----------------|------|
| 2 | `eeg_controls/phase_baseline.py` | no (ridge regression) | `eeg_controls/results/phase/` | about 3 min per participant |
| 4 | `eeg_controls/reference_maps.py` | no | `eeg_controls/results/reference/` | about 2 min per participant |
| 1 | `eeg_controls/run_horizon.py` | yes, KG-GT v2 per horizon and participant | `results/v2_horizon/`, `outputs/checkpoints_v2_horizon/` | 20-30 min per run |

## 2. Phase baseline: how much of E is the task phase?

```
env/Scripts/python.exe -m eeg_controls.phase_baseline --participants all
```

Ridge regression from event-locked features only (no EEG), scored like v2 on the test series:
`phase` (all task events), `phase_weight` (the same, per object weight), `coarse` (wide bumps, no phase
boxcars), `cue` (LED-on only). `phase_vs_E.csv` puts them next to E and K of `results/v2/standard.csv`.
If `cue` or `coarse` already reach E, E is a lift-locked template, not muscle-specific cortical drive.

## 4. Reference maps: ERD and CMC against the rollout maps

```
env/Scripts/python.exe -m eeg_controls.reference_maps --participants all
```

Alpha and beta ERD (window before first touch and lift-off, and the hold, against the second before the
hand starts) and beta CMC (15-30 Hz, hold, raw EMG rectified) per electrode, from all series; Spearman
correlation with the rollout maps of E in `outputs/interpretability_v2/` (read only), per participant
(sign-flip p over participants) and for the group maps (electrode-shuffle p).

## 1. Forecast horizon with a causal model

```
env/Scripts/python.exe -m eeg_controls.run_horizon --participants all --horizons-ms 0,200,500,1000
env/Scripts/python.exe -m eeg_controls.run_horizon --summary-only        # table over finished runs
```

Sets `model.causal`, `tokens.causal` and `tokens.horizon` (see `v2/causal.py`): every output uses inputs up
to its own time, the inputs are built from past samples only (except the 0.1 s force gate of the cache),
and input token t predicts the target at t + h. Per run: K / E / F metrics, the residual test, and the
EEG gain per task phase (`pre_move` = the last second before the hand starts). Runs resume and finished
folders are skipped. `--smoke` (1 epoch) with `--results` and `--checkpoints` in a scratch folder checks
the code without touching the real folders.

Expected outcome if the EEG carries movement intention: the gain (F - K, residual r, pre_move skill)
grows with h. If it stays at zero, the EEG adds nothing even where the kinematics cannot see ahead.

Tests: `tests/test_v2_causal.py` (no output depends on a later input; causal tokens, band power and
velocities use no future sample; the horizon shift pairs input t with target t + h).

## Phase 1: weight check, ridge per phase, electrode subsets and eye control

Four questions on the current preprocessing, before anything is changed (design: `eeg_controls/DESIGN_phase1.md`,
plan: `eeg_controls/PLAN_phase1.md`). The easiest way to run everything is the notebook `eeg_controls_phase1.ipynb`
(generated by `tools/build_eeg_controls_phase1_notebook.py`): a markdown guide per section (what each figure should show
for "good for EEG" against "only timing or artifacts"), a RUN cell and a PLOT cell. Figures go to
`eeg_controls/results/phase1/figures/`. Every new option is opt-in (`eeg.channels`, `eeg.eye_regress`,
`training.freeze_kin`); with the keys absent, `v2` behaves as before. Claude never runs the training parts: you run them.

| part | module | question | trains? | output |
|------|--------|----------|---------|--------|
| W | `eeg_controls/weight_check.py` | does E give light, medium and heavy lifts different levels? | no | `eeg_controls/results/phase1/weight/` |
| R | `eeg_controls/phase_ridge.py` | does the EEG add anything beyond past task events, and does a ridge per phase help? | no | `eeg_controls/results/phase1/phase_ridge/` |
| S, E | `eeg_controls/run_conditions.py` | what survives with central electrodes only, edge electrodes only, eyes regressed out (against `all_frozen`)? | E and fusion only (K loaded and frozen) | `results/v2_controls/`, `outputs/checkpoints_v2_controls/` |

Run times on the GTX 1660 Ti:

| part | training | size |
|------|----------|------|
| W | none | about 1 min per participant |
| R | none | about 3 min per participant and horizon |
| S, E | E and fusion only | 4 conditions (`all_frozen`, `central`, `edge`, `eye_clean`) x 3 horizons x 12 participants = 144 runs |

Freezing K roughly halves a horizon run: about 10 to 15 minutes instead of 20 to 30, so the 144 runs of S and E take about
24 to 36 hours. Every runner skips finished runs unless `--overwrite`, and `--smoke` (1 epoch, 5 null draws) with outputs in a
scratch folder checks the code.

### W. Weight check

```
env/Scripts/python.exe -m eeg_controls.weight_check --participants all
```

Non-causal v2 checkpoints (`outputs/checkpoints_v2`), test series. Per lift with a known weight (CurW 1, 2, 4), the level of
the target, K, E, F and E_cal (E times one gain per muscle and window fitted on the validation lifts) in the hold window
(lift-off + 0.5 s to replace - 0.2 s) and the load window (first touch to lift-off). Writes `levels.csv`, `stats.csv`
(per muscle: level per weight, heavy/light ratio, rho with weight, slope, size ratio) and `group.csv` (Wilcoxon over
participants). Figures W1 to W4.

### R. Ridge per phase and causal timing baseline

```
env/Scripts/python.exe -m eeg_controls.phase_ridge --participants all --horizons-ms 0,200,500
```

Causal horizon checkpoints (`outputs/checkpoints_v2_horizon`). Ridge on the residual of K with `none` (intercept only),
`eeg`, `events` (past-event bumps, lags 0 to 3 s after each of the 8 task events, only events at or before the token) and
`both`, fitted pooled or per task phase. Writes `phase_ridge.csv`, `summary.csv` (including skill(both) - skill(events) with
its Wilcoxon p, and for per_phase `gain_vs_none` = skill(X) - skill(none) with its p) and one file per run in `runs/`
(reused on the next call). Figures R1 to R3.

The per_phase skill is not causal: the phase labels come from the events at the target time, so a per-phase fit (even its
intercept) already knows the phase. Read it only through `both - events` and `X - none`, never against 0.
Runs computed before the `none` feature set was added are reused from `runs/` and lack it: delete
`eeg_controls/results/phase1/phase_ridge/runs/` to recompute (the CLI and the notebook warn about such files).

### S and E. Electrode subsets and eye control

```
env/Scripts/python.exe -m eeg_controls.run_conditions --participants all --conditions all_frozen,central,edge,eye_clean --horizons-ms 0,200,500
env/Scripts/python.exe -m eeg_controls.run_conditions --summary-only        # table and tests over finished runs
```

Flags: `--kin-checkpoints` (default `outputs/checkpoints_v2_horizon`, where K is loaded from), `--checkpoints`
(`outputs/checkpoints_v2_controls`), `--results` (`results/v2_controls`), `--baseline` (`results/v2_horizon`, the `all` condition),
`--smoke`, `--overwrite`, `--summary-only`. Conditions: `all_frozen` (all 32 electrodes, the reference), `central` (C3, Cz,
C4, CP1, CP2, CP5, CP6), `edge` (Fp1, Fp2, F7, F8, T7, T8, TP9, TP10, P7, P8, PO9, PO10, O1, Oz, O2), `eye_clean` (regress on
Fp1, Fp2, F7, F8 and drop them). Every condition loads K and keeps it frozen, so `all_frozen` is the fair reference: `all`
(the joint-trained horizon runs) differs from the subsets also in the training procedure.

Before the first run, every needed K checkpoint is checked (it must exist and agree with the condition config in the
model, tokens, history and loss blocks); if any is missing or different, all of them are listed and nothing trains. A run
that fails is logged with its traceback to `{results}/failures.log`, the loop goes on, and the number of failed runs is
printed at the end. After each fit the `kin.*` tensors are compared with the loaded checkpoint (an error names the first
that differs). With `--smoke`, a `--results` or `--checkpoints` left at its default gets `_smoke` appended
(`results/v2_controls_smoke`), and the folders written to are printed.

Writes `summary.csv` and `vs_all.csv` (column `reference`: each subset minus `all_frozen` and minus `all`, `all_frozen`
minus `all`; paired two-sided Wilcoxon over participants). Figures C1 to C3.

Tests: `tests/test_eeg_controls_phase1_notebook.py` (cells, markers, generator match, module imports) and the tests of each
module in `tests/`.
